# Prévia de 20/10/2026 — limites e roteiro

Não equivale a uma certificação de todos os casos em produção. Não usar dados
pessoais de terceiros na apresentação nem criar registros fictícios no banco real.

## Conferido

- FaeHub: suíte com 198 testes aprovados e um teste opcional de backup PostgreSQL
  não executado. Inclui matrícula, contas, notas, chamada por aula, atividades,
  mensagens, documentos, direção, recuperação de acesso e autenticador.
- FaeHub publicado: painel e nove páginas do aluno abriram na sessão existente.
- Ensaio local descartável: login/navegação de professor, direção e responsável;
  cadastro integrado FaeNet dos quatro perfis; publicação, seguir e mensagem.
- Correções FaeNet: envio do cadastro, atualização do feed sem duplicação e
  navegação para Mensagens com destinatário. Regressões cliente versionadas.

## Antes de apresentar

1. Usar contas próprias/consentidas de cada perfil. Demos antigas do FaeHub não
   comprovam identidade para a FaeNet: precisa concluir o convite/ativação.
2. Reabrir os apps para carregar o JavaScript atualizado, antes de preencher forms.
3. Ensaiar aluno → professor → direção → responsável com os dados autorizados.
4. Na FaeNet, confirmar cadastro → perfil → seguir → publicação → mensagem.
5. FaeMatch possui perfis ilustrativos e projetos locais ao navegador; suporte
   ainda está em breve. Apresentar essas partes como demonstração/protótipo.
6. Entrega real de e-mail e execução do backup agendado não foram retestadas neste
   ensaio. Não afirmar homologação desses serviços externos com base em mocks.

O ensaio local não substitui entrar com as quatro contas reais que serão usadas.
